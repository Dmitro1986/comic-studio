# Аудит: AiPULT Execution, Self-Healing ScenarioStore и WebP карточки комиксов

## 1. Контекст
Пользователь обратил внимание на несколько критических проблем:
1. Ошибка 502 Bad Gateway (`PROCESS_FAILED`) при запуске команды ревизии через карточку AiPULT (`python3 scripts/revise_scenario.py --scenario-id d69d6b41 --feedback "Смени стиль рисунка на anime"`).
2. Исчезновение из списков дашборда и интерфейса комиксов и моделей, которые находились в процессе редактирования или ревизии.
3. Медленная загрузка тяжелых PNG подложек карточек во вкладке «Комиксы».

## 2. Что сделано

### 2.1. Устойчивость ревизии и подрезка подписей в `py/scenario/writer.py`
- Выявлена причина падения `revise_scenario.py`: нейросеть MiniMax генерировала подписи длиной 7-8 слов.
- Жесткая проверка `_validate_revision_response` выбрасывала `ValueError("panel #1 caption exceeds 6 words")`, возвращая exit status 1 для подпроцесса runner.js.
- В функции `revise_scenario` добавлен автоматический тримминг подписей перед валидацией (`panel["caption"] = " ".join(words[:MAX_CAPTION_WORDS])`), что делает процесс устойчивым к мелким отклонениям количества слов от LLM.

### 2.2. Self-Healing Reconciliation в `web/lib/scenario_store.js` и `scripts/revise_scenario.py`
- Обнаружена причина пропадания редактируемых моделей: при ручной ревизии или запуске CLI скрипт записывал `"status": "draft"` внутрь файла `data/scenarios/rendered/<id>.json`.
- `ScenarioStore.list()` при несоответствии директории и статуса выбрасывал `SCENARIO_STATE_MISMATCH` и исключал модель из выдачи API.
- В `web/lib/scenario_store.js` реализован авто-восстановитель (Self-Healing Reconciliation): при разхождении статуса и папки файл автоматически перемещается в целевую папку (`data/scenarios/draft/<id>.json`) или синхронизирует статус без потери записей.
- В `scripts/revise_scenario.py` обновление файла теперь сохраняет результат в папку `data/scenarios/<target_status>/` с зачисткой старого файла в прежней папке.
- На старте сервера мгновенно восстановлены все 4 ранее потерянных сценария (`666934c3`, `9c282ded`, `c7197a2f`, `d69d6b41`).

### 2.3. Ускорение загрузки карточек в «Комиксах» через WebP
- В `web/routes/comics.js` эндпоинт `GET /api/comics` теперь по умолчанию отдает WebP-URL (`/comics/<id>.webp`) в поле `url` и сопутствующее поле `url_png`.
- В `ui/app.js` метод `loadComics()` обновлен так, что обложки карточек подгружают формат `.webp` как основной источник элемента `<picture>` / `<img>`, снижая объем передаваемых данных и увеличивая скорость отображения интерфейса в браузере.
