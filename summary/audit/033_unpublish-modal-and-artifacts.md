# Аудит: Улучшение логики снятия с публикации и UI

## 1. Контекст
После исправления ошибки со сменой статуса при снятии с публикации выяснилось, что:
1. Пользователь хотел добавить модальное окно с подтверждением для действия "Вернуть в Готовые", аналогичное окну удаления.
2. В процессе выяснилось, что удаление сгенерированных HTML и WebP артефактов при `unpublish` ломало логику: после повторной публикации (без ререндера) файл `.html` отсутствовал и кнопка HTML на сайте выдавала `404 Not Found`.

## 2. Что сделано
- **UI (ui/index.html & ui/app.js)**: 
  - Добавлена новая модалка `#unpublish-modal` с текстом подтверждения снятия с публикации.
  - Настроены обработчики событий для перехвата нажатия кнопки `.unpublish`, открытия окна подтверждения и вызова `apiFetch` только после подтверждения.
- **Backend (web/routes/scenarios.js)**:
  - Из обработчика `POST /api/scenarios/:id/unpublish` убрана логика удаления файлов `.html` и `.webp` (через `fs.promises.unlink`). Таким образом сгенерированные комиксы остаются нетронутыми при временном снятии с публикации.
