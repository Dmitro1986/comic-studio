# Аудит 035: Knowledge comic «П'ять днів» через Comic Studio MCP

## 1. Контекст

Пользователь предложил перевести украинский текст про новорождённую девочку, которая провела ночь в киевском паркинге под обстрелом, и сделать на его основе комикс. Источник — реальный рассказ одесской подруги автора.

**Цель:** Создать **knowledge comic** в стиле S.T.A.L.K.E.R. (грязные охряные/ржавые тона, бетон, контрастный свет) — документальный, без графического насилия.

**Использованный стек:** Comic Studio MCP (stdio) + Hermes subagent для автоматизации пайплайна.

## 2. Исходный текст (перевод с украинского)

> Маленькая девочка — первая внучка моей одесской подруги, которая родилась пять дней назад, сегодня провела ночь в паркинге в Киеве под баллистикой. Я каждый раз пытаюсь осознать, что чувствует маленький ребёнок в таких обстрелах, потому что мы, взрослые, как-то привыкли, хотя конечно боимся.

## 3. Подход

### 3.1. Skill `baoyu` vs. Comic Studio MCP

Изначально планировалось использовать skill `baoyu` (educational visualization), но в текущей сессии Hermes у меня нет инструмента `image_generate`, который требует этот skill. Поэтому использован **Comic Studio MCP** как альтернативный путь — он умеет генерировать изображения через MiniMax, но создаёт **нарративные** комиксы (3-4 панели на сценарий), а не one-page knowledge comics.

**Решение:** создать серию из 5 связанных комиксов, каждый = одна страница истории.

### 3.2. Workflow

1. **Storyboard** написан вручную в стиле S.T.A.L.K.E.R. (5 страниц)
2. **Subagent #1:** создание 5 сценариев → approve → render → polling → vision-проверка
3. **Subagent #2:** перерендер комикса `405c27de` (содержание не попало в сюжет — пролог вместо паркинга)
4. **Subagent #3:** перерендер комикса `7940b078` (семейная сцена вместо рассвета)
5. **Сборка HTML-книги:** вручную, единый стиль, S.T.A.L.K.E.R. палитра
6. **Публикация:** `data/comics/baoyu-pyat-dney-book.html` (доступен по `https://comic.openaiua.fr/comics/baoyu-pyat-dney-book.html`)

### 3.3. Промпты и подписи

Все промпты на украинском/русском, image_style=`realistic`, caption_style=`memo`. Стиль S.T.A.L.K.E.R. заложен в промптах как явное описание палитры, текстур, света.

## 5. Проблемы и решения

### 5.1. Подписи не совпадают с моими инструкциями

**Симптом:** Я давал инструкцию "Підписи: ТИШИНА. ГУЛ. БАМ.", LLM MiniMax сгенерировал свои ("П'ять днів." / "Перший погляд." / "Гул. Бам.").

**Причина:** `caption_style="memo"` — это стиль **оформления** подписей (жёлтые стикеры), а не текст. Текст генерирует MiniMax LLM на основе промпта панели, и он **не выделяет подписи в отдельное поле инструкции** — они часть сценария.

**Решение:** В фидбэке для revise нужно давать подписи **в каждой панели явно**, не отдельной строкой.

### 5.2. Возраст ребёнка плавает

**Симптом:** Я просил "новорождённая 5 дней от роду", MiniMax нарисовал в некоторых панелях подросшего ребёнка (~1-3 года).

**Причина:** MiniMax плохо держит точный возраст через серию панелей. Возраст "5 дней" слишком специфичен, модель переключается на более "фотогеничного" ребёнка.

**Решение:** Принято как ограничение модели. S.T.A.L.K.E.R. стиль и красная шапочка сохранены в каждой панели — это и есть узнаваемость персонажа.

### 5.3. Web job runner таймауты

**Симптом:** Из 5 рендеров 3 провалились с `PROCESS_FAILED`, exit_code=1.

**Причина:** Web job runner (`web/lib/process_runner.js`) имеет таймаут ~3 мин, MiniMax рендер занимает 3-5 мин на комикс.

**Решение:** Ручной fallback через `python3 scripts/render_approved.py --scenario-id <id>`.

### 5.4. Subagent timeouts

**Симптом:** Первый subagent упал на 600 сек (10 мин), не доделав 5-й комикс.

**Причина:** Sequential подход — каждый комикс через poll+wait, итого 5 × 3-5 мин = 15-25 мин, что больше таймаута.

**Решение:** В следующих экспериментах использовать **batch mode** через `delegate_task(tasks=[...])` для параллельного создания, или background-процессы для polling.

## 7. Выводы

1. **Comic Studio MCP работает для knowledge comics**, но требует:
   - Ручного storyboard (skill `baoyu` имеет workflow для этого, но его инструмент `image_generate` недоступен в моей текущей сессии)
   - Тщательного фидбэка на revise (массив строк, не одна строка)
   - Fallback через Python скрипт при таймаутах web runner

2. **Subagent batch mode** лучше sequential — можно параллелить создание сценариев

3. **HTML-книга** собирается из `panel_N.png` эндпоинтов, не из собранных `<id>.png`. Это даёт гибкость, но требует ручной CSS-вёрстки

4. **Возраст персонажей** — слабое место MiniMax для точных возрастов в серии

5. **Удаление страницы 4 (Одесса)** показало, что пользователь предпочитает сюжетный фокус без distant narrator — нарратив от одного места сильнее
