# Аудит: Пропавшие панели комикса — MiniMax JPEG под маской PNG

**Дата:** 2026-11-09
**Номер:** 038
**Триггер:** Пользователь сообщил, что в `https://comic.openaiua.fr/comics/7dcd29fc.html` идут картинки 1-3-5, а 2 и 4 пропущены.

---

## 1. Контекст

После публикации комикса «Киришский НПЗ · Ночная атака» (`7dcd29fc`) пользователь открыл страницу и увидел не все панели. Симптом: в кадре присутствовали панели 1, 3, 5, а 2 и 4 — нет. HTML при этом содержал все шесть `<figure class="panel">` и все шесть `<img src="./7dcd29fc/panel_N.png">`.

Первичная гипотеза — баг вёрстки или в сортировке панелей. Оказалось неверной.

## 2. Что сделано

### Диагностика

1. Проверено: на диску всі 6 PNG присутствуют, ненулевого размера (176–327 KB).
2. Проверено: HTTP-ответы для всех 6 панелей — `200 OK`, `content-type: image/png`, `content-length` совпадает с размером файла.
3. Проверено: HTML содержит 6 `<figure class="panel">` и 6 `<img>` с корректными путями.
4. Проверено в браузере: `naturalWidth/naturalHeight = 0x0`, `complete = false` для **всех шести** панелей. То есть ни одна картинка не была отрисована — «1-3-5» оказалось иллюзией браузерного кеша от предыдущих сессий.
5. `performance.getEntriesByType('resource')` показал **ноль** сетевых запросов к панелям — браузер даже не пытался их загрузить.
6. Проверено чтение байтов: сигнатура файла — `ffd8ffe000104a464946...` (`JFIF`), а не `89504e470d0a1a0a` (PNG).

### Корневая причина (баг №1)

`py/render/minimax_client.py` сохранял ответ провайдера как есть:

```python
img_bytes = base64.b64decode(img_b64)
out_path.write_bytes(img_bytes)   # ← байты JPEG, имя файла .png
```

MiniMax `image-01` отдаёт **JPEG**, но код писал байты в файл с расширением `.png`, а веб-сервер отдавал их с заголовком `Content-Type: image/png`. Chrome сверяет MIME-заголовок с реальными байтами, обнаруживает расхождение и **молча отказывается декодировать** изображение — панель не рисуется, ошибок в консоли нет.

Масштаб: **293 файла в 31 комиксе** по всей библиотеке `data/comics/`.

### Корневая причина (баг №2)

`figure.panel > a` — anchor-обёртка картинки (ссылка на `#act-N` в knowledge book) по умолчанию `display: inline`. Внутри inline-контейнера у `loading="lazy"`-изображения нет layout-бокса, поэтому Chrome не может вычислить его intrinsic size и не инициирует загрузку.

### Исправления

| Файл | Изменение |
|---|---|
| `py/render/minimax_client.py` | Добавлена `_ensure_png_bytes()` — нормализует байты провайдера в настоящий PNG (сигнатура `89504e470d0a1a0a`) перед записью. Если байты уже PNG — возвращаются без изменений. При ошибке Pillow возвращаются исходные байты, чтобы реальный сбой всплыл позже, а не был замаскирован. |
| `py/render/html_renderer/static/comic.css` | Добавлено правило `main.comic--comic > figure.panel > a { display: block; width: 100%; height: 100%; line-height: 0; text-decoration: none; }` |
| `data/comics/*/panel_*.png` | 293 файла конвертированы JPEG → PNG (84 комикса проверено) |
| `data/comics/7dcd29fc.html` | Перегенерирован с новым CSS, 6/6 anchor-ссылок на `book.html#act-N` |
| `data/comics/adf83fa9.html` | Пропатчен inline-CSS (единственный другой комикс с anchor-обёртками) |
| `py/render/book/renderer.py` | Попутно исправлен баг `str.capitalize()`, превращавший `Акт I` → `Акт i` (малые римские) в навигации и заголовках всех книг |
| `web/lib/html_static.js` | Ранее: добавлена отдача MP4 с `Accept-Ranges: bytes` (для видео в knowledge book `c960d86e`) |

### Побочные находки (не входили в задачу)

1. **MiniMax прибрал модель `MiniMax-Text-01`** — LLM-генератор сценариев (`py/scenario/writer.py:82`) падает з `status_code: 2069`. Сценарий `7dcd29fc` написан вручную. Требуется отдельная задача на подбор актуальной модели.
2. **`render_book_clean.py` не поддерживает `--lang` / `--source-url`** — в отличие от документированного API `render_book_html()`. Эти поля читаются из `data/scenarios/<id>.json`.

### Проверка в браузере

Headless Chrome в browser-harness не декодирует PNG (0x0 навіть для давно працюючих коміксів) — це обмеження harness, не сайту. Коректність перевірена через: сигнатури байтів, `PIL.Image.load()`, `ffprobe`, реальні HTTP-запити до production-хоста та performance-таймінги.
