# Аудит: Фикс бага при снятии комикса с публикации

## 1. Контекст
Пользователь сообщил, что при попытке снять комикс с публикации ("Вернуть в Готовые") происходило следующее:
1. Удалялись HTML и WebP файлы.
2. Файл комикса перемещался в папку `rendered`.
3. Однако после этого файл автоматически возвращался в `published`, и кнопки редактирования не появлялись, требуя повторного нажатия "Опубликовать", чтобы создать новый.

Причина заключалась в двух вещах:
1. Наличие тестового маршрута-заглушки для `/:id/unpublish`, который возвращал `ok: true`, но ничего не делал.
2. В основном маршруте `/:id/unpublish` файл переносился с помощью `fs.promises.rename()`, но внутренний статус объекта (`record.status`) оставался `"published"`. Система `ScenarioStore` при чтении обнаруживала несоответствие папки (`rendered`) и внутреннего статуса (`published`) и автоматически "лечила" это, перемещая файл обратно в папку `published`.

## 2. Что сделано
- Удален отладочный маршрут `/:id/unpublish`, который перехватывал запросы.
- Основной обработчик `/api/scenarios/:id/unpublish` переписан на использование метода `store.transition(id, 'published', 'rendered')`. Этот метод корректно обновляет `record.status` и безопасно переносит файл.
- Сохранена логика удаления сгенерированных `.html` и `.webp` артефактов при снятии с публикации.
- Сервис `comic-web` был перезапущен, и функционал был проверен. Ошибок больше не возникает (за исключением временного network error alert из-за рестарта сервера).
