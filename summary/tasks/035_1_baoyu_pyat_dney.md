## Технические находки

### Подписи — не подчиняются явным инструкциям

MiniMax LLM, генерирующий подписи, **игнорирует** строку `Підписи: ТИШИНА. ГУЛ. БАМ.` в промпте — он придумывает свои. Подписи — это часть сценария, не отдельная инструкция.

**Workaround:** В `revise` фидбэке указывать желаемые подписи **внутри описания каждой панели** явно:
```
ПАНЕЛІ:
1. [описание] Підпис під панеллю: "ТИШИНА."
2. [описание] Підпис під панеллю: "ГУЛ."
```

### Возраст ребёнка плавает

MiniMax плохо держит "5 дней от роду" через серию — рисует подросшего ребёнка. Стиль и красная шапочка сохраняются стабильно.

**Workaround:** Не указывать точный возраст, ограничиться "немовля / newborn / 5 days old" + "red knit cap".

### Web job runner таймауты

3 из 5 рендеров провалились с `PROCESS_FAILED` (timeout ~3 мин), MiniMax рендер занимает 3-5 мин.

**Workaround:** Fallback через `cd /home/ubuntu/projects/comics && python3 scripts/render_approved.py --scenario-id <id>`.

### Revise feedback должен быть массивом строк

`POST /api/scenarios/:id/revise` принимает `feedback` как **массив**, не одну строку. Иначе → `400 REVISION_FEEDBACK_REQUIRED`.

**Workaround:** Разбивать на массив фокусных пунктов:
```json
{
  "feedback": [
    "ПОВНИЙ ПЕРЕГЕНЕРАЦІЯ. Це НЕ пролог...",
    "ПАНЕЛЬ 1: ...",
    "ПАНЕЛЬ 2: ...",
    "ПАНЕЛЬ 3: ...",
    "СТИЛЬ: S.T.A.L.K.E.R. БЕЗ графіки насильства"
  ]
}
```

## Извлечённые уроки

1. **Skill baoyu не доступен** в текущей сессии Hermes (нет `image_generate`). Использован Comic Studio MCP как альтернатива.
2. **Subagent batch mode** предпочтительнее sequential для параллельного создания сценариев.
3. **HTML-книга из панелей** даёт гибкость (можно убирать/добавлять панели), но не показывает собранный вид комикса.
4. **Пользователь предпочитает сюжетный фокус** — distant narrator (страница про Одессу) был отвергнут.
5. **S.T.A.L.K.E.R. стиль через текстовое описание** работает в MiniMax — модель понимает "іржа, бетон, брудний жовтий, реалістичний, без теплої кімнати".
