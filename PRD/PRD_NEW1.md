## 1. Контекст и Проблематика

Проект **Comic Studio** представляет собой автоматизированную платформу генерации комиксов на базе AI (LLM + MiniMax Image Generation), с доступом через Web UI, Telegram Bot, Telegram MiniApp и MCP Server.

В ходе системной эксплуатации и аудита выявлены следующие точки роста:
1. **Высокий вес графических артефактов**: Использование формата PNG без сжатия приводит к передаче тяжелых файлов (1–3 MB на страницу), что замедляет загрузку Web UI и MiniApp на мобильных устройствах.
2. **Избыточные вызовы платного API MiniMax**: При ревизиях или повторном рендеринге неизменившиеся панели повторно генерируются через API MiniMax, приводя к лишним затратам времени (3–5 минут) и бюджета.
3. **Задержка обновления статусов (Polling)**: Фронтенд делает опрос сервера каждые 10 секунд, создавая задержку восприятия и лишнюю нагрузку на сервер.
4. **Отсутствие мультиконтейнерного деплоя**: Отсутствие стандартизированного Docker-окружения усложняет развертывание на новых VPS.
5. **Ограниченные форматы экспорта**: Доступен только просмотр на сайте и PNG/HTML; отсутствует экспорт в PDF и паки для соцсетей (Instagram Carousel / Telegram).

## 2. Цели (Goals) и Не-цели (Non-Goals)

### Цели (Goals)
* **G1 (Сжатие артефактов)**: Сократить сетевой размер комиксов и панелей на 60–80% за счет генерации WebP/AVIF копий с сохранением оригиналов.
* **G2 (Кэш генераций)**: Сократить время повторного рендеринга незатронутых панелей до <5 секунд за счет хэш-кэширования промтов MiniMax.
* **G3 (Real-time статусы)**: Внедрить Server-Sent Events (SSE) для мгновенного отображения прогресса создания/рендеринга без polling.
* **G4 (Универсальность зависимостей Python)**: Обеспечить работу нечеткого поиска сценариев в Python без привязки к бинарным C++ зависимостям (`rapidfuzzy`).
* **G5 (Стандартизация деплоя)**: Подготовить `Dockerfile` и `docker-compose.yml` для развертывания проекта в 1 клик на любых серверах.
* **G6 (Расширенный экспорт)**: Добавить генерацию PDF и ZIP-пакетов панелей для соцсетей.
* **G7 (Безопасность API)**: Защитить публичные эндпоинты от спама и перерасхода API-лимитов с помощью Rate Limiting.
* **G8 (Совместимость веток)**: Сохранить 100% совместимость со спецификой обеих веток (`main` и `demo-production`).

### Не-цели (Non-Goals)
* **N1**: Не отменять поддержку PNG/HTML (сохраняется полный backward-compatibility для Telegram/Notion).
* **N2**: Не переводить бэкенд на тяжелые СУБД (сохраняется файловое атомарное JSON-хранилище `data/scenarios/`).
* **N3**: Не отключать эвристический резолвер AiPULT (эвристика остаётся основным быстрым путем).

## 3. Функциональные Требования (FR)

### FR-1: WebP/AVIF Оптимизация изображений
* При генерации панелей и сборке комиксов создаются версии `.webp` (качество 82%).
* Web UI и MiniApp используют тег `<picture>` с поддержкой WebP и фоллбэком на PNG.
* Эндпоинты `/comics/<id>.webp` и `/comics/<id>/panel_<N>.webp` отдаются с правильными заголовками кэширования (`Cache-Control: public, max-age=31536000, immutable`).

### FR-2: Хэш-кэширование генераций MiniMax (Prompt-Image Cache)
* Перед вызовом MiniMax рассчитывается хэш `sha256(character_prompt + scene_prompt + image_style + seed)`.
* Кэш хранится в `data/.cache/images/<hash>.png`.
* Если хэш найден в кэше, генерация пропускается, и используется готовый артефакт (время выполнения 0.1 сек).

### FR-3: Real-Time прогресс через SSE (Server-Sent Events)
* Эндпоинт `GET /api/jobs/:id/stream` предоставляет SSE-поток событий (`job_created`, `panel_rendered`, `job_completed`, `job_failed`).
* Фронтенд Web UI и AiPULT автоматически подключаются к SSE при запуске генерации/рестайла и обновляют UI без задержек.

### FR-4: Встроенный Pure-Python нечеткий поиск для scenario_resolver
* Реализовать алгоритм Левенштейна / Jaro-Winkler на чистом Python без внешних C-компилируемых зависимостей.
* `py/lib/scenario_resolver.py` прозрачно переключается: `rapidfuzzy` (если установлен) -> `pure_python_fuzzy` (fallback).

### FR-5: Мультиформатный Экспорт (PDF & Social Pack)
* Эндпоинт `GET /api/comics/:id/export?format=pdf` генерирует печатный PDF документ.
* Эндпоинт `GET /api/comics/:id/export?format=social-zip` генерирует ZIP-архив с квадратизированными панелями (1080x1080) и текстовым описанием для постов в Telegram / Instagram.

### FR-6: Docker & Инфраструктура
* `Dockerfile` соберите мультистадийную сборку (Node.js 22 + Python 3.12 venv + Caddy reverse proxy).
* `docker-compose.yml` поддерживает запуск одной командой `docker compose up -d`.

### FR-7: Rate Limiting и Защита API
* На эндпоинты `/api/scenarios/create` и `/api/aipult/chat` накладывается лимит (например, 10 запросов в минуту с одного IP).

## 4. Архитектура и Совместимость веток

```
┌──────────────────────────────────────────────────────────────────────────┐
│                             Web UI / MiniApp                             │
│                     (SSE Stream + WebP Picture Tags)                     │
└────────────────────────────────────┬─────────────────────────────────────┘
                                     │ HTTP / SSE
┌────────────────────────────────────▼─────────────────────────────────────┐
│ Web API Layer (Node.js Express)                                          │
│ ├── /api/jobs/:id/stream  (SSE)                                          │
│ ├── /api/comics/:id/export (PDF / Social ZIP)                             │
│ └── express-rate-limit                                                   │
└────────────────────────────────────┬─────────────────────────────────────┘
                                     │ Subprocess / IPC
┌────────────────────────────────────▼─────────────────────────────────────┐
│ Python Layer                                                             │
│ ├── py/render/ (HTML + WebP Converter)                                   │
│ ├── py/lib/scenario_resolver.py (Pure-Python Fuzzy Fallback)             │
│ └── py/lib/image_cache.py (SHA256 Prompt Cache)                          │
└──────────────────────────────────────────────────────────────────────────┘
```

2. Обновление документации и проведение тестов на обеих ветках.
